============================

Upstream:      https://github.com/RoboDojo-Benchmark/RoboDojo

Commit date:   2026-08-07 11:11:43 +0800

Version 0.3.0 adds the lazy RLinf/RPent simulation bridge and CPU contract
tests. The environment.patch is unchanged from 0.2.0; the articulation drive-reset
backport is recorded separately below.
assets_root() now returns the containing directory, matching the documented
ROBODOJO_ASSETS_ROOT contract also when the environment variable is unset.

The vendored tree is the tree this integration was validated against, not a
pristine upstream copy. Upstream's public release is eval-only: it ships
src/eval_client/ and no steppable environment client at all. There are four
deliberate differences and no others; they are itemised below.

1. Environment patch -- robodojo_runtime/PATCHES/environment.patch
--------------------------------------------------------------------------
sha256:   fa5f6219bb36cb1fdf957a63fbc326bbec5bff786f90185efb78ae6d919806a0

3. Code-root / data-root split -- env/global_configs.py
--------------------------------------------------------------------------
  ROOT_DIR     = os.environ.get("ROBODOJO_ROOT") or os.path.join(current_dir, "..")
  ASSETS_ROOT  = os.environ.get("ROBODOJO_ASSETS_ROOT") or ROOT_DIR
  ASSETS_PATH  = os.path.join(ASSETS_ROOT, "Assets")
  OBJECTS_PATH = os.path.join(ASSETS_ROOT, f"Assets/Object/{BENCHMARK}")
  ROBOTS_PATH  = os.path.join(ASSETS_ROOT, "Assets/Robots")
  ENV_CONFIG_PATH = os.path.join(ROOT_DIR, "env_cfg")

Why:      a wheel cannot carry a multi-gigabyte Assets/ tree, and RoboDojo
          derives both the code root and the data root from the location of
          env/. Splitting them lets the code ship as a distribution while the
          scene data stays on its own volume. With neither variable set the
          values are byte-for-byte upstream's.
